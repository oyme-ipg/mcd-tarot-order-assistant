# 🍔✨ 麦当劳塔罗运势 · mcd-tarot-fortune

> 把塔罗的仪式感塞进一个汉堡盒里：先算运势，再抽牌，最后用一张牌换一份**真实在售**的麦当劳商品。

一个纯 Python 标准库实现的命令行技能（Skill）。用生日、星座、生命灵数与**当日真实月相**生成五维运势报告，再让用户从 1-22 凭直觉选号抽大阿尔卡那塔罗牌，最后揭晓与之绑定的麦当劳在售商品（含 SKU、官方图片、价格），并解释「为什么今天适合吃它」。

**气质**：神秘但不装神弄鬼，有趣但不胡说八道，轻松但有仪式感。
**原则**：凡是「真实」的部分（月相、商品、价格）必须是真的；凡是「玄学」的部分（评分、牌意、宜忌）写得像那么回事，但语气留三分玩笑余地。

```bash

cd ~/.workbuddy/skills/mcd-tarot-fortune

# 2) 开启今日运势
$PY scripts/fortune.py daily
```

零第三方依赖，系统 `python3` 也能跑。所有命令默认输出**排版好的 Markdown**，直接呈现给用户即可；加 `--json` 拿结构化数据（同样带 `markdown` 字段）。

## 交互流程（4 个阶段）

| 阶段 | 触发语 | 动作 |
| --- | --- | --- |
| Stage 0 建档 | 首次使用 / 缺生日与职业 | 问生日（阳历）+ 职业，执行 `profile` |
| Stage 1 运势 | 「开启今日运势」「麦当劳塔罗」 | 执行 `daily`，原样输出报告，**停在引导语** |
| Stage 2 选号 | 用户报数字 | 校验 1-22；**绝不替用户选号、绝不剧透** |
| Stage 3 揭晓 | 数字合法 | 执行 `draw`，输出牌意 + 商品 + 适配理由 |
| Stage 4 再抽 | 用户再报数字 | 同一数字同一天结果一致，次日重新洗牌 |

> ⚠️ Stage 2 是硬约束：神秘感是这个技能一半的价值。禁止提前展示任何一张牌的对应关系或商品。

## 命令参考

```bash
# 录入/更新档案（--name 区分多人，同一个人始终用 default）
$PY scripts/fortune.py profile --birthday YYYY-MM-DD --occupation "职业" [--name default] [--city 上海]

# 今日运势
$PY scripts/fortune.py daily [--name default] [--date YYYY-MM-DD] [--json]

# 抽牌（1-22）
$PY scripts/fortune.py draw --number 7 [--name default] [--date YYYY-MM-DD] [--json]

# 22 张牌 ↔ 商品映射表（剧透用）
$PY scripts/fortune.py cards

# 查真实月相
$PY scripts/fortune.py moon [--date YYYY-MM-DD]
```

退出码：`0` 正常，`3` 参数错误（生日格式错、数字不在 1-22）。

## 核心算法

| 模块 | 实现 | 说明 |
| --- | --- | --- |
| 月相 | `moon_phase()` — Meeus 低精度天文算法 | 算当日 12:00（北京时）日月黄经差，输出相位角、照明度、月龄，映射八个相位 |
| 星座 | `zodiac_of()` | 12 星座边界 + 四象（火/土/风/水）偏置 |
| 生命灵数 | `life_path()` | 生日逐位求和，保留 11/22/33 大师数 |
| 职业角色 | `job_group()` | 关键词匹配到 9 类角色（内容创作者 / 前线业务岗 / 技术型岗位 …），影响事业建议措辞 |
| 五维评分 | `compute_scores()` | 事业·财运·感情·健康·人际，由 seed 混合生日+日期+月相+星座偏置生成 |
| 确定性随机 | `class Rand` | SHA-256 计数器模式：同一 seed 永远同一结果，**一天内运势不漂移** |
| 正逆位 | `draw_card()` | 基础逆位率 0.32，亏月 +0.06、低分 +0.08、超高分 -0.10 |
| 适配理由 | `_build_why()` | 由牌面绑定维度 + 当日最高/最低维度 + 月相走向 + 职业角色共同生成，非套话 |

**月相真实性已核对**：2026-10-23 盈凸月 / 照明 89% / 月龄 11.5 天；2026-10-26 12:12 满月；2026-11-09 新月。不要凭印象改写月相，也不要用农历月份糊弄。

## 数据来源

- **月相**：本地天文算法计算，无网络依赖。
- **商品与价格**：麦当劳中国官方菜单接口实时返回值。
  采集门店：麦当劳上海黄浦华旭国际大厦餐厅（`storeCode=1450713`），到店自提价，采集日 2026-10-23。
  每条含 `sku`、官方图片 URL、现价、原价。

价格会随城市、渠道、时间浮动，因此：

1. 展示时保留脚本脚注里的价格来源与免责说明，不要删。
2. 用户问「我这附近多少钱」或要真下单时 → 走 MCP 实时校准（见 [mcp_integration.md](mcp_integration.md)），以实时价为准。
3. 商品下架时保持映射不变，如实说明并推荐同价位替代，**不要编 SKU**。

## 与 MCP 的关系

本技能**离线即可完整运行**（内置菜单快照）。麦当劳点餐 MCP 是可选增强，只在两种时机介入：

1. **价格校准** — 用户问本地实时价
2. **真实下单** — 用户明确要买

详见 [mcp_declaration.json](mcp_declaration.json)（声明依赖哪些工具、权限边界）与 [mcp_integration.md](mcp_integration.md)（调用链、字段映射、降级策略）。

## 边界

| 情况 | 处理 |
| --- | --- |
| 未建档就要算 | 提示缺生日与职业，走 Stage 0 |
| 生日格式错误 | 要求 `YYYY-MM-DD` 阳历 |
| 数字不在 1-22 | 笑着请重选，不抽牌 |
| 商品缺图/图裂 | 保留文字信息，不删 SKU 与价格 |
| 当天重复抽同一数字 | 结果一致，说明「今天它认准你了」 |
| 给朋友算 | `profile --name 名字` 建独立档案 |

只存生日、职业、城市，**不记录任何敏感信息**。运势是娱乐，不给投资、医疗、法律结论；不在占卜里夹带促销话术。
